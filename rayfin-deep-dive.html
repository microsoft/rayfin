01 Rayfin とは何か

Rayfin は Microsoft が開発する、フルマネージドな Backend-as-a-Service（BaaS） プラットフォームです。 バックエンドのインフラを構築・運用することなく、チームがアプリケーションを高速に開発・出荷できるようにすることを目的としています。

その中心的なアイデアはシンプルです。TypeScript のデコレーターでデータモデルを定義するだけで、 プラットフォームが以下をすべて自動的にプロビジョニング・管理します。

🗄️

Database

スキーマは TypeScript のデコレーターから自動生成される Fabric 上のマネージド SQL データベース。

🔐

Authentication

セッション管理・トークン処理・サインインフローが組み込み済み。Fabric SSO に対応。

🔌

Data APIs

デコレートしたクラスから GraphQL エンドポイントを自動生成。コントローラー不要。

📦

Storage

ファイルストレージを型安全なクライアント経由で操作。

🌐

Hosting

ビルド済みフロントエンドを 1 コマンドで公開 URL に配信。

🤖

Agent-ready

「エージェント時代」を前提に設計。AI エージェント向けの永続状態と MCP ツールを提供。

Fabric Apps としての一面 Rayfin は Microsoft Fabric 上では 「Fabric Apps（プレビュー）」 という製品として提供されています。 Fabric Apps は Rayfin SDK を基盤とし、開発者が Fabric 上でデータ駆動アプリを統一されたワークフローで構築できるようにします。

02 なぜ Rayfin なのか

Microsoft Fabric という土台

Rayfin は Microsoft Fabric の上に構築されています。 Fabric は、集中管理されたデータ検出・アクセス制御・ガバナンス機能を提供します。これにより組織は、 データアクセス・共有・コンプライアンスをワークロード横断で一貫して管理できます。

つまり Rayfin アプリは、エンタープライズグレードのセキュリティとガバナンスを標準装備した状態で生まれます。 コンプライアンスを犠牲にすることなく、高速に開発できるのです。

「エージェント時代」への最適化

Rayfin は AI エージェントがバックエンドを組み立てる時代を前提に設計されています。 GitHub Copilot などのエージェントと相性が良く、@microsoft/rayfin-mcp（Model Context Protocol ツール）や ビルダー向けガイドを通じて、エージェント主導の開発フローをサポートします。

03 3 つのコアコンセプト

Rayfin SDK は「デコレーター駆動」のプログラミングモデルであり、次の 3 要素を組み合わせています。

🏷️

Decorator-driven schema

TypeScript のデコレーターでデータモデル・権限・リレーションを定義。スキーマは 1 か所（コード）が真実の源。

⚙️

Automatic API generation

デコレートしたクラスがそのまま GraphQL エンドポイントに。コントローラーのコードを書く必要はありません。

🛡️

Type-safe clients

生成される TypeScript クライアントが、クエリとミューテーションをコンパイル時に検証します。

Single source of truth TypeScript モデルへの変更は、データベーススキーマ → API エンドポイント → クライアントの型まで スタック全体に自動的に波及します。フィールドをリネームすれば、権限チェックも型も一緒に更新されます。

04 クイックスタート

新規プロジェクトの雛形を作成し、デプロイして動かすまでは実質 2 コマンドです。

# 新しい Rayfin プロジェクトを雛形生成
npm create @microsoft/rayfin@latest

# Fabric にデプロイして起動
npx rayfin up

create CLI は、データモデル・認証・API・デプロイ可能なアプリまで、必要なものを一式スキャフォールドします。 あとはビジネスロジックに集中するだけです。

05 デコレーター駆動のデータモデル

データ構造は、@microsoft/rayfin-core のデコレーターを使った TypeScript クラスで定義します。 次は Todo エンティティの完全な例です。行レベルの認可ポリシーも同じ場所で宣言している点に注目してください。 

import {
  entity, role, text, boolean, date, uuid,
} from '@microsoft/rayfin-core';

@entity()
@role('authenticated', '*', {
  policy: (claims, item) => claims.sub.eq(item.user_id),
})
export class Todo {
  @uuid() id!: string;
  @text({ min: 1, max: 100 }) title!: string;
  @boolean() isCompleted!: boolean;
  @date() createdAt!: Date;
  @date({ optional: true }) dueDate?: Date;
  @text() user_id!: string;
}

Rayfin はこのデコレーターを解析し、次を生成します。

  • データベースのテーブル定義（テーブル・カラム・制約・インデックス）
  • GraphQL API エンドポイント
  • 行レベルの認可ルール
  • 型安全なクライアントメソッド

デコレーターリファレンス

エンティティ

デコレーター用途例
@entity()クラスをデータベースエンティティとしてマーク@entity() class Product

プロパティ（型マッピング）

デコレーターデータベース型TypeScript 型
@uuid()UNIQUEIDENTIFIERstring
@text()NVARCHARstring
@int()INTnumber
@decimal()DECIMALnumber
@bool() / @boolean()BITboolean
@date()DATETIME2Date

多くのプロパティデコレーターは { optional: true } や { min, max } といったオプションを受け取り、 NULL 許容や検証制約を宣言できます。

権限

デコレーター用途
@role()ロールベースの権限（行レベルセキュリティ）を定義

06 コードが API になるまで

Fabric アプリを作成すると、あなたのコードは次のステージを流れていきます。

Developer

好みのエディターでアプリを記述します。

TypeScript

エンティティクラスを TypeScript で書きます。

Decorators

@entity / @uuid / @text / @role などでクラスとフィールドを注釈します。

Schema

CLI がデコレート済みクラスを、データベーススキーマ・権限ポリシー・API 構成にコンパイルします。

APIs

スキーマが GraphQL エンドポイントとして公開されます。

Client

生成された RayfinClient が、型安全なデータ／認証クライアントを提供します。

Application

フロントエンドがそのクライアントを使ってデータを読み書きします。

07 型安全クライアント SDK

GraphQL API に対する CRUD 操作は、@microsoft/rayfin-client の RayfinClient を通じて行います。 クライアントはエンティティのフィールドをコンパイル時に把握しているため、存在しないフィールドを参照するとその場でエラーになります。 

import { RayfinClient } from '@microsoft/rayfin-client';

const client = new RayfinClient();

// TypeScript は Product のフィールドを理解している
const products = await client.data.products.query()
  .select(['id', 'name', 'price'])
  .execute();

// 存在しないフィールドはコンパイルエラー
const invalid = await client.data.products.query()
  .select(['nonexistentField'])  // ❌ TypeScript error
  .execute();
リファクタリング安全性 エンティティのフィールドを変更すると、クエリ・ミューテーション・権限チェックまで型レベルで追随します。 「バックエンドとフロントエンドの型ずれ」という古典的なバグが構造的に発生しません。

08 認証と認可

認証（Authentication）

セッション管理・トークン処理・サインインフローは組み込みです。デプロイ済みアプリでは Fabric SSO（Microsoft Entra ID） を構成し、 ローカル開発時にはメール＋パスワードを利用できます。デプロイ後の本番環境では、認証は Fabric SSO に一本化され、 それ以外の認証プロバイダーは利用できません。

認可（Authorization）

権限は @role デコレーターでデータモデルと同じ場所に定義します。policy 関数で行レベルのアクセス制御を表現できます。 

@entity()
@role('authenticated', ['create', 'read', 'update', 'delete'], {
  policy: (claims, item) => claims.sub.eq(item.userId)
})
export class UserDocument {
  @uuid() id!: string;
  @text() userId!: string;
  @text() content!: string;
}

このアプローチにより、次が保証されます。

  • セキュリティルールが、保護対象のデータのすぐ隣で暮らす
  • 型安全なポリシー式が、コンパイル時にエラーを捕捉する
  • エンティティのフィールドをリファクタリングすると、権限チェックも自動的に更新される

09 アーキテクチャと Fabric 連携

Fabric アプリは、バックエンドを構成する一連のサービス（アプリホスティング・データベース・GraphQL API・認証）を備えた マネージドサービスとして Fabric 上で動作します。ホスティング・ネットワーク・スケーリングは Fabric が管理します。 

                    ┌──────────────────────────────────────────┐
   npx rayfin up →  │        Fabric App (managed service)      │
                    │                                          │
                    │   https://<your-app>-app.rayfin          │
                    │            .windows.net/                 │
                    │                                          │
                    │   /api/graphql  →  Data API (GraphQL)    │
                    │   /auth         →  Authentication        │
                    │   /storage      →  File storage          │
                    └───────────────┬──────────────────────────┘
                                    │ child items
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
     ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
     │ SQL Database │      │Authentication│      │Static Content│
     │  in Fabric   │      │  (Entra SSO) │      │  (OneLake)   │
     └──────────────┘      └──────────────┘      └──────────────┘

子サービス（Child services）

rayfin up でデプロイすると、rayfin.yml の構成をもとに子サービスが作成され、Fabric ポータル上で Fabric アプリの子アイテムとして現れます。

子サービス提供内容ポータルでの操作
SQL database in Fabric TypeScript デコレーターから適用されたスキーマを持つマネージド SQL データベース。 DB 参照・クエリエディターでの実行・接続文字列コピー。ポータルでは読み取り専用で、スキーマ変更は必ずコード（rayfin up）から行う。
Authentication Microsoft Entra ID（SSO）を用いた Fabric ブローカー認証。ユーザーは既存の Fabric ID でサインイン。 SQL データベース上で認証済みユーザーを確認。
Static Content ビルド済みフロントエンド資産（HTML/CSS/JS）を OneLake ストレージで公開 URL 配信。 ホスティング URL の確認。デプロイのたびに資産を更新。

アプリのエンドポイント

各 Fabric アプリは、全サービスへのアクセスを提供する単一のエンドポイントを持ちます。

https://<your-app>-app.rayfin.windows.net/

ポータルでのアイテム権限

ワークスペースのロールはアイテムレベルの権限を上書きしません。組織内でアプリを共有するには、対象ユーザーに Run and interact 権限が必要です。

権限できること
Run and interact（既定）デプロイ済みアプリを開いて利用し、バックエンド API を呼び出す。ワークスペースメンバーは既定で付与。
Edit (Write)rayfin up でのコードデプロイ、スキーマ変更、設定更新、子サービス管理。
Reshare他ユーザーへのアクセス付与。ワークスペースの admin ロールが必要。

前提条件

  • Fabric capacity：ワークスペースに Fabric 容量を割り当てる必要がある（サービスは容量ユニットを消費）。
  • テナント管理者設定：管理者が Fabric Apps ワークロードを有効化する必要がある（Fabric 管理ポータル → テナント設定 → Fabric Apps (preview) を Enabled）。
  • リージョン：Fabric Apps はまだ全リージョンでは利用できません。

11 CLI リファレンス

CLI は新規プロジェクトの雛形生成、ローカルインフラの起動、スキーマ変更の同期、Fabric へのデプロイを担います。

コマンド目的
npm create @microsoft/rayfin@latestテンプレートから新規プロジェクトを作成
npx rayfin upプロジェクトを Fabric にデプロイ
npx rayfin up db applyデータベーススキーマの変更を適用
npm run devフロントの変更を Fabric 上のバックエンドに対してローカルでテスト

典型的な開発サイクル

データモデルの定義・変更

デコレーター付きの TypeScript クラスを追加・更新する。

ローカルでテスト

npm run dev で、フロントの変更を Fabric 上のバックエンドに対して検証する。

Fabric にデプロイ

npx rayfin up でマネージドサービスにデプロイし、スキーマ変更を適用する。

12 ローカル開発 EXPERIMENTAL

Rayfin はクラウドリソース不要の、純粋なローカル開発体験もサポートします（現時点では実験的）。 Rayfin を試したり、オフラインで開発したりするのに最適です。ローカルではフルスタックを Docker で動かして高速に反復し、 本番準備ができたら Fabric にデプロイします。ローカル開発時の認証にはメール＋パスワードを利用できます。

試すには Todo Local Experimental テンプレート から始めるのがおすすめです。

13 ユースケースと適性

Rayfin が向いているケース

⚡

高速プロトタイピング

事前構成済みインフラで、アイデアから公開 URL まで数分。

📊

社内ツール・ダッシュボード

バックエンドの定型コードなしで、認証付き管理画面を構築。

🔎

データ探索・可視化

Fabric データを GraphQL で問い合わせ、カスタムフロントで表示。

🤖

AI・エージェントアプリ

永続状態を必要とする AI エージェント向けに、構造化されたバックエンドを提供。

向いていないケース

  • 複雑な多段トランザクションやストアドプロシージャを必要とするアプリ
  • Fabric SSO とメール＋パスワード以外の、カスタム認証プロバイダーを必要とするアプリ

14 セキュリティ責任分界

🏢

Fabric が提供するもの

Fabric SSO（Entra ID）／@role による行レベルセキュリティ／HTTPS／PKCE／ワークスペース・アイテムレベルの権限。

👤

あなたの責任

シークレット・API キー・機微データをコードや静的資産、リポジトリに含めない（静的コンテンツは公開 URL 配信）。SSO 後にアプリが何を見せ・何をさせるかの制御。最小権限の付与。取り扱うデータの法令・コンプライアンス責任。

重要 静的コンテンツは公開 URLから配信されます。フロントエンドの資産に秘密情報を埋め込まないでください。 認証済みユーザーが何を閲覧・操作できるかは、あなたのコードが制御します。
